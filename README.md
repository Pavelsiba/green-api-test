# GREEN-API чат

Тестовое задание «Фронтенд разработчик React»: веб-интерфейс для отправки и получения текстовых
сообщений через [GREEN-API](https://green-api.com/). Внешний вид — по образцу
[web.max.ru](https://web.max.ru/).

**Демо:** https://pavelsiba.github.io/green-api-test/

Мессенджер — **WhatsApp**. Инстанс GREEN-API привязывается к мессенджеру на телефоне, а устанавливать
MAX на личный телефон я не стал. П. 1 задания разрешает сделать интерфейс для WhatsApp вместо MAX.

## Сценарий

1. Войти по данным инстанса GREEN-API.
2. Ввести номер получателя — откроется новый чат.
3. Написать сообщение и отправить (метод `sendMessage`).
4. Ответ собеседника появится в чате без перезагрузки: приложение опрашивает очередь уведомлений
   (`receiveNotification` → `deleteNotification`).

## Что нужно для входа

В [личном кабинете GREEN-API](https://console.green-api.com/) создайте инстанс WhatsApp и авторизуйте
его по QR-коду. На странице инстанса есть три значения для формы входа:

| Поле | Пример |
| --- | --- |
| `apiUrl` | `https://7201.api.green-api.com` |
| `idInstance` | `7201234567` |
| `apiTokenInstance` | токен из кабинета |

Чтобы входящие сообщения и статусы доставки попадали в очередь, в настройках инстанса включите
уведомления: `incomingWebhook`, `outgoingMessageWebhook`, `outgoingAPIMessageWebhook`,
`outgoingWebhook`, `stateWebhook`. Без них очередь уведомлений всегда пуста.

Данные для входа хранятся только в `localStorage` вашего браузера и уходят только в GREEN-API.
Кнопка «Выйти» их удаляет.

## Локальный запуск

Нужен [Bun](https://bun.sh/) 1.3+.

```bash
git clone https://github.com/Pavelsiba/green-api-test.git
cd green-api-test
bun install
bun run dev
```

Откройте адрес, который напечатает Vite (обычно http://localhost:5173).

Необязательно: чтобы не вводить данные каждый раз в режиме разработки, скопируйте `.env.example`
в `.env` и заполните `VITE_API_URL`, `VITE_ID_INSTANCE`, `VITE_API_TOKEN_INSTANCE` — форма входа
заполнится сама. В production-сборку эти значения не попадают.

## Стек

React 19, TypeScript, Vite, TanStack Query, jotai, Mantine, CSS Modules, zod/mini, Vitest,
Testing Library, Biome, Steiger, knip. Бэкенда нет: GREEN-API разрешает запросы из браузера (CORS),
поэтому приложение — статическая SPA.

## Как устроено

Код разложен по [Feature-Sliced Design](https://feature-sliced.design/):
`app → pages → widgets → features → entities → shared`.

- **`shared/api`** — транспорт GREEN-API. Каждый ответ проверяется строгой схемой zod: лишнее поле
  даёт предупреждение в консоли и пропускается, отсутствующее или неверное — ошибка. Ошибки —
  `ApiError` с типом (сеть, неверные данные, лимит запросов, антифрод-лимит 469 и т.д.). HTTP 200
  с `{ status: false }` тоже считается ошибкой.
- **Хранилище сообщений — кэш TanStack Query.** Отправка — мутация с оптимистичным сообщением:
  оно появляется сразу со статусом «отправляется», затем получает id с сервера. Приём — запрос
  с `refetchInterval`: одна итерация забирает уведомление, применяет его к кэшу и удаляет из
  очереди. Уведомления, которые не удалось разобрать, тоже удаляются, иначе очередь встанет.
- **Одно событие может прийти дважды** (повтор уведомления, ответ `sendMessage` и уведомление
  о нашем же сообщении), поэтому все обновления кэша идемпотентны по id сообщения, а статусы
  доставки не откатываются назад.
- **Тема** — токены дизайн-системы MAX (тема `space`, светлая и тёмная), снятые с CSS web.max.ru.

## Сверх минимального сценария

Задание просит минимальный набор функций. Помимо сценария выше в приложении есть:

- история переписки при открытии чата (`getChatHistory`, последние 100 сообщений);
- список чатов за последнюю неделю (`lastIncomingMessages` / `lastOutgoingMessages`) с последним
  сообщением и счётчиком непрочитанных;
- статусы доставки (отправлено, доставлено, прочитано, ошибка);
- светлая и тёмная тема, вёрстка для мобильной ширины.

## Ограничения

- Только личные чаты и текстовые сообщения. Фото, видео и прочее показываются подписью
  («Фото», «Видео»…), группы в список не попадают.
- Время сообщений — по часам телефона, к которому привязан инстанс.
- Проверка номера (`checkWhatsapp`) вызывается только для новых чатов: у метода жёсткий лимит,
  за превышение GREEN-API включает антифрод на 2 часа.
