# GREEN-API чат

Тестовое задание «Фронтенд разработчик React»: отправка и получение текстовых сообщений через
[GREEN-API](https://green-api.com/) в интерфейсе по образцу [web.max.ru](https://web.max.ru/).

**Демо:** <https://pavelsiba.github.io/green-api-test/>

Мессенджер — **WhatsApp**: инстанс GREEN-API привязывается к мессенджеру на телефоне, а MAX на личный
телефон я ставить не стал. П. 1 задания разрешает WhatsApp вместо MAX.

## Сценарий

1. Войти по данным инстанса GREEN-API.
2. Ввести номер получателя — откроется новый чат.
3. Отправить сообщение (`sendMessage`).
4. Ответ появится без перезагрузки: приложение опрашивает очередь уведомлений
   (`receiveNotification` → `deleteNotification`).

## Что нужно для входа

В [личном кабинете](https://console.green-api.com/) создайте инстанс WhatsApp и авторизуйте его
по QR-коду. Там же — `apiUrl` (например, `https://7201.api.green-api.com`), `idInstance`
и `apiTokenInstance`.

В настройках инстанса включите уведомления `incomingWebhook`, `outgoingMessageWebhook`,
`outgoingAPIMessageWebhook`, `outgoingWebhook`, `stateWebhook` — без них очередь всегда пуста.

Данные для входа хранятся только в `localStorage` браузера, «Выйти» их удаляет.

## Локальный запуск

Нужен [Bun](https://bun.sh/) 1.3+.

```bash
git clone https://github.com/Pavelsiba/green-api-test.git
cd green-api-test
bun install
bun run dev
```

Чтобы в dev форма заполнялась сама, скопируйте `.env.example` в `.env` и заполните `VITE_*`.
В production-сборку эти значения не попадают.

Проверки: `bun run typecheck`, `bun run lint` (Biome + Steiger), `bun run lint:dead` (knip),
`bun run test`. CI гоняет их на каждый пуш и PR в `main` и деплоит `main` на GitHub Pages.

## Стек и устройство

React 19, TypeScript, Vite, TanStack Query, jotai, Mantine, zod/mini, Vitest, Biome. Бэкенда нет:
GREEN-API разрешает запросы из браузера. Код — по [Feature-Sliced Design](https://feature-sliced.design/).

- **Хранилище сообщений — кэш TanStack Query.** Отправка — оптимистичная мутация, приём — запрос
  с `refetchInterval`: забрать уведомление, применить к кэшу, удалить из очереди.
- **Обновления идемпотентны по id сообщения**: одно событие может прийти дважды (ответ
  `sendMessage` и уведомление о нём же), статусы доставки назад не откатываются.
- **Контракт API строгий.** Каждый ответ проверяется strict-схемой zod. Любое расхождение —
  ошибка `badResponse` (уведомление удаляется, запись истории показывается как неподдерживаемая),
  причина — в консоли. Как реагировать на изменение контракта, решает владелец продукта, не фронт.
- **Тема** — токены дизайн-системы MAX, снятые с CSS web.max.ru.

## Сверх минимума и ограничения

Сверх сценария: история чата (100 сообщений), список чатов за неделю со счётчиком непрочитанных,
статусы доставки, тёмная тема, мобильная вёрстка.

- Только личные чаты и текст; медиа показывается подписью («Фото», «Видео»…).
- Время сообщений — по часам телефона инстанса.
- `checkWhatsapp` вызывается только для новых чатов: за превышение лимита GREEN-API включает
  антифрод на 2 часа.
